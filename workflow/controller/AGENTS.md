# Workflow Controller

- `controller.go` is the plumbing (informers, workqueues, throttler, sync manager); `operator.go` is the logic. Each reconciliation builds a `wfOperationCtx` (`woc`) from a **DeepCopy** of the informer object — never mutate cache objects. `operate()` runs task-result reconciliation, pod reconciliation, then `reconcileTemplate` from the entrypoint (also used for exit handlers and hooks): it resolves the template and its arguments and hands the processed template to `executeProcessedTemplate`, which lives with its helpers in `operator_template_execution.go` (node preparation, deadline and parallelism constraints, synchronization, memoization, retries, post-execution handling) and dispatches per template type (container, containerSet, script, suspend, resource, data, http, plugin, steps, DAG). Operations self-limit to `MAX_OPERATION_TIME` (30s) and requeue.
- Steps and DAG templates share one `Engine` (`engine.go`); `dag.go` and `steps.go` only adapt the template's tasks to `dag.Task` (Steps through `StepAdapter`, each step given a synthetic dependency on the previous group) and call `Execute`. Per cycle the Engine asks the pure evaluator in `workflow/controller/dag` which tasks are ready, waiting or omitted, then loops until a pass changes nothing: create Omitted nodes, resolve each ready task into a `DesiredTask` (`desired_state.go`) and dispatch it through the `TaskReconciler` (`reconciler_k8s.go`, which calls `executeProcessedTemplate`), assess TaskGroup and StepGroup phases, run lifecycle and exit hooks (`hook_handler.go`); finally it assesses the boundary node. Every phase change goes through `markNodePhase`, which refuses transitions not in the table in `node_phase_sm.go`. Read `workflow/controller/dag/README.md` before changing readiness, omission, retry or task-group assessment.
- `woc.wf.Spec` and `woc.execWf.Status` are banned (`forbidigo` linter, configured in `.golangci.yml`): use `woc.execWf.Spec` (the template-merged spec) and `woc.wf.Status`. Escape hatch: `//nolint:forbidigo // not-woc-misuse` on the line.
- `workflowpod.go` turns a template into a pod. Two pod layouts, deliberately confined to `workflowpod_layout.go`: legacy (`init` init-container + `wait` sidecar) and init-less beta (single `supervisor` container, argoexec via image volume). Don't scatter layout conditionals elsewhere.
- Outputs channel: the executor **never writes the Workflow**. It creates/patches a `WorkflowTaskResult` CR (named after the node ID); the controller merges it in `taskResultReconciliation` (`taskresult.go`). A node is only truly done when its phase is fulfilled **and** its task result is synced — `NodeStatus.Fulfilled()` checks both (`Phase.Fulfilled(node.TaskResultSynced)`); daemoned nodes are the exception, fulfilled as soon as they leave `Pending`.
- HTTP and Plugin templates get no pod: they go into a `WorkflowTaskSet` CR consumed by a single per-workflow **agent pod** (`agent.go`, `argoexec agent`), which patches results back into the TaskSet status. Executor plugins run as sidecars on the agent pod.
- Node model (`pkg/apis/workflow/v1alpha1/workflow_types.go`): `Status.Nodes` is `map[nodeID]NodeStatus`; node `ID` is a hash of the tree-path `Name`; `BoundaryID` points at the enclosing template; `OutboundNodes` are a template invocation's exit nodes.
- Large node status is compressed and, if still too big, offloaded to SQL (`workflow/hydrator/`, `persist/sqldb/`). Any code reading nodes outside the controller must hydrate first.
